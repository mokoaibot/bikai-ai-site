# Брифинг — читать первым

Этот файл — не техническая документация (она в README.md), а то, что
не лежит в коде: как заказчик любит работать, какие договорённости уже
есть, и какие грабли в этой песочнице уже собраны.

**Работаем с заказчиком долгосрочно** (подтверждено 08.10.2026): заказчик
ведёт проект именно с этим агентом — «следующего агента» нет, и просить
его «заново» пока не планируется. Это не одноразовая передача, а живой
файл, который обновляется по ходу работы. Если окружение запустилось
с нуля — всё равно прочитайте его: особенности песочницы (ниже) никуда
не деваются.

## Как заказчик любит работать

- Короткие ответы, без воды. Если сомневаетесь — короче, а не длиннее.
- Не любит, когда решения/архитектура усложняются быстрее, чем он успевает
  их понять. Если строите что-то новое — объясняйте просто, по шагам,
  и не бойтесь переспросить, нужна ли вообще сложность.
- Ценит автономность в исполнении (не спрашивать разрешения на каждый шаг),
  но хочет понимать, что происходит и почему — короткий отчёт после
  действия лучше, чем длинный вопрос до него.
- Готов сказать прямо, если что-то не нравится (дашборд, формулировки,
  дизайн) — это рабочая обратная связь, а не повод оправдываться.
- Общение на русском.

## Стоящие правила (не переспрашивать, просто соблюдать)

- **Скоуп — только BIKAI.** Другие бренды из общего КП (Winmedic, Chiwell,
  Kedi) — не в работе, не трогать, если явно не попросят.
- **Не включать цены/сметы в планы по BIKAI**, которые показываются
  заказчику, даже если они есть в исходных файлах ТЗ/КП.
- **Не предлагать повторно** общую концепцию "ИИ-агенты как услуга" —
  это уже обсуждено и не нужно.
- Автономный push в GitHub — на усмотрение исполнителя, не нужно спрашивать
  разрешения на каждый коммит.
- Пуш/пулл — **только через `python3 engine/sync_git.py push|pull|status`**,
  никогда raw `git push` (см. раздел про окружение ниже, почему).
- Минимизировать количество папок верхнего уровня, не плодить "ещё одну
  служебную папку" без необходимости.
- Структура репозитория принципиальна для заказчика: он явно просил простую
  навигацию (где инструкции, где код, где конкретное направление) — см.
  README.md. Не возвращайтесь к смешению кода и рабочих материалов.

## Среда — особенности песочницы (чтобы не наступать на одни грабли)

- Песочница **сбрасывается между репликами**: установленные pip-пакеты
  (`streamlit` и т.д.), фоновые процессы (дашборд, превью-серверы) и
  `.git/config` (включая `git remote`) **не сохраняются**. Это не баг,
  не повод для тревоги — просто переустановить/перезапустить заново.
- `.env` **сохраняется** (это не в списке исключений Arena) — реальный
  `GITHUB_TOKEN`/`GITHUB_REPO_URL` там есть и работают.
- Поэтому `git remote` каждую сессию пустой — но `engine/sync_git.py`
  сам чинит его из `.env` при каждом вызове. Просто используйте его,
  не пытайтесь чинить `git remote` руками.
- GitHub — **не официальный коннектор Arena** (это обычный git + токен,
  самодельная интеграция). Google Drive и Notion — официальные коннекторы,
  но не подключены; **Notion не вариант для заказчика** (регион
  блокирует, VPN принципиально не хочет).
- Текущий `GITHUB_TOKEN` **не имеет scope `workflow`** — нельзя пушить/
  менять файлы в `.github/workflows/` этим токеном. Поэтому GitHub Pages
  для `bikai.by` развёрнут через прямой пуш ветки `gh-pages`
  (`engine/deploy_gh_pages.py`), а не через Actions.
- Репозиторий: публичный `github.com/mokoaibot/bikai-ai-site`, `.env`
  настроен под него, GitHub Pages включён, сайт живой:
  `https://mokoaibot.github.io/bikai-ai-site/`.
