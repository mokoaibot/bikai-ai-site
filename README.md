# Главная инструкция

Это единственный файл, с которого стоит начинать. Он главный — остальные
инструкции он просто перечисляет, ничего не дублируя.

**Сначала прочитайте [`HANDOFF.md`](HANDOFF.md)** — там то, что не лежит
в коде: как заказчик любит работать, какие договорённости уже есть, и
какие грабли в этой песочнице уже собраны. Заказчик работает с этим
агентом долгосрочно, файл обновляется по ходу работы.

## Кто это делает

Исполнитель один — ИИ-агент (Arena.ai), работающий в чате. Ниже —
не "агенты" и не "оркестратор над агентами", а просто папки с памятью:
что делать, что уже сделано и чему научились.

## Где что искать

```
directions/     — по одной папке на каждое реальное направление/клиента
  bikai/
    INSTRUCTIONS.md   ← главная инструкция по BIKAI (прочитать перед работой)
    catalog/          ← сам сайт-каталог (код сборки + готовый сайт)
    knowledge/        ← что уже узнали/проверили именно по BIKAI
    logs/             ← лог действий именно по BIKAI
    raw_inputs/       ← файлы, которые прислал клиент

shared/          — общее для всех направлений, не привязано к одному клиенту
  knowledge/     ← общие паттерны/ошибки
  logs/          ← общий лог + история чата
  playbooks/     ← многоразовые методички по типам задач
  exports/       ← снимки архитектуры для переноса в другую сессию

engine/          — техника (движок + дашборд + файлы состояния).
                   Сюда заглядывать не обязательно — это не рабочие материалы.

local_dropzone/  — сюда вы кидаете файлы мне; я сам раскладываю их по
                   directions/<направление>/raw_inputs/
```

## Как найти "главную инструкцию" для конкретного направления

`directions/<название>/INSTRUCTIONS.md` — всегда одно и то же имя файла.
Сейчас есть одно направление: [`directions/bikai/INSTRUCTIONS.md`](directions/bikai/INSTRUCTIONS.md).

## Что не нужно трогать руками

Всё внутри `engine/` — это код и служебные файлы состояния
(`engine/state/*.json`). Если что-то там не так — просто скажите, я поправлю.

## Синхронизация с GitHub

`python3 engine/sync_git.py push|pull|status` — сам чинит remote и
подставляет токен из `.env` на момент выполнения (токен нигде не
сохраняется на диске).
